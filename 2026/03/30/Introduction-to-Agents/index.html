Introduction to Agents

2026-03-30 | 技术

本系列文章为Kaggle-Google教程5-Day AI Agents Intensive Course with Google学习笔记。

1. Introduction to Agents

📖 1. 核心背景：范式转移 (The Paradigm Shift)

现状 vs 未来

  • **传统AI (Predictive/Generative AI)**：被动的、离散的任务执行者。
    • 典型场景：回答问题、翻译文本、生成图片。
    • 局限：每一步都需要人类持续的Prompt引导，无法独立完成长链路任务。
  • **AI智能体 (AI Agents)**：主动的、目标导向的系统。
    • 定义：不仅仅是模型，而是模型+工具+编排的完整应用。它们能够制定计划、采取行动并根据反馈迭代，直到达成目标。
    • 价值：从“辅助内容生成”转向“自主解决问题”。

💡 一句话总结：如果说LLM是“大脑”，那么Agent就是给大脑装上了“手脚”和“神经系统”，让它能真正干活。

🏗️ 2. 智能体架构：四大核心组件 (The Anatomy of an Agent)

构建一个Agent不仅仅是调用API，它需要四个基本组件协同工作：

🧠 1. 大脑 (The Brain) - 模型层

  • 核心：基础语言模型（LLM）。
  • 职责：负责推理（Reasoning）、规划（Planning）和决策。
  • 关键能力：理解复杂指令，从上下文中提取关键信息。

🛠️ 2. 手脚 (The Hands) - 工具层

  • 定义：连接内部推理与外部世界的桥梁。
  • 组成：
    • API扩展：调用外部服务（如发送邮件、查询天气）。
    • 代码执行：运行Python脚本进行计算或数据处理。
    • 数据检索：访问向量数据库或RAG系统获取实时信息。

⚡ 3. 神经系统 (The Nervous System) - 编排层

  • 职责：管理Agent的“认知循环”。
  • 功能：
    • **记忆管理 (Memory)**：短期记忆（当前对话上下文）与长期记忆（历史经验）。
    • 状态维护：记录当前任务进行到哪一步。
    • 推理策略：如ReAct（Reasoning + Acting）、CoT（Chain of Thought）。

🛡️ 4. 躯体 (The Body) - 部署与运行时

  • 职责：将原型转化为生产级服务。
  • 包含：宿主环境、安全沙箱、日志监控、鉴权机制。

🔄 3. 认知循环：Agent是如何思考的？ (The Cognitive Loop)

一个Agent在接收到任务后，会经历一个标准的5步循环：

  1. 接取任务 (Get the Mission)
    • 用户或触发器输入高层目标（例如：“帮我查一下订单#12345到哪了”）。
  2. 扫描场景 (Scan the Scene)
    • 感知环境：用户是谁？现在几点？有哪些工具可用？记忆里有什么？
  3. 深思熟虑 (Think It Through)
    • 分解与规划：LLM制定计划。
    • 示例：“我需要先去数据库查订单详情，拿到快递单号，再去查物流API。”
  4. 采取行动 (Take Action)
    • 调用工具：执行 find_order("12345")。
  5. 观察与迭代 (Observe and Iterate)
    • 获取反馈：工具返回“运单号是ZYX987”。
    • 闭环：回到第3步，利用新信息继续规划下一动作（调用 check_shipping("ZYX987")），直到任务完成。

📈 4. 能力分级：从聊天机器人到多智能体协作 (Levels of Agents)

Google将Agent的能力成熟度分为四个等级，这为我们的技术演进提供了清晰的路线图：

Level 0: 核心推理系统 (The Core Reasoning System)

  • 描述：裸奔的LLM。
  • 能力：仅依赖预训练知识。
  • 缺陷：有幻觉，无法获取实时信息（问它“昨晚比赛谁赢了”会失败）。

Level 1: 联网的问题解决者 (The Connected Problem-Solver)

  • 描述：LLM + 工具。
  • 能力：能识别意图并调用外部API获取答案。
  • 示例：RAG应用，或能联网搜索的Chatbot。

Level 2: 战略性规划者 (The Strategic Problem-Solver)

  • 描述：具备复杂规划和上下文管理能力。
  • 能力：能处理模糊的多步骤任务。
  • 示例：“帮我规划一次东京旅行”，它会自动拆解为查机票、订酒店、排行程、算预算等多个步骤，并自行串联。

Level 3: 协作式多智能体系统 (Collaborative Multi-Agent System)

  • 描述：专家团队协作。
  • 架构：一个“项目经理Agent”负责拆解任务，分发给“市场调研Agent”、“代码编写Agent”、“测试Agent”等。
  • 价值：实现复杂业务流程的端到端自动化。

🏗️ 5. 工程化

5.1 选型策略（The Brain）

  • 选型原则：不迷信跑分，关注 Agent 基础能力（复杂推理、工具使用稳定性）。
  • 混合模型路由：使用前沿大模型（如 Gemini 3.0 Pro）处理复杂规划，用轻量模型（如 Flash）处理简单分类，平衡成本与延迟 。

5.2 工具设计

  • RAG (检索增强生成)：给予 Agent 访问知识库的“借书证”，减少幻觉。
  • Actions (执行)：通过 API 改变世界（发邮件、写数据库）。
  • Function Calling：利用 OpenAPI 规范或 MCP (Model Context Protocol) 协议，让模型准确生成函数调用参数 。

5.3 Agent Ops：管理不确定性

由于 Agent 具有概率性，传统的单元测试（assert output == expected）不再适用。需要引入 Agent Ops：

  • 以质量为指标：使用 LLM-as-a-Judge（大模型裁判）对 Agent 的输出进行评分（准确性、合规性、语气）。
  • 基于指标的开发 (Metrics-Driven Development)：建立“金标准”数据集，每次迭代都需跑通评估集。
  • 可观测性：使用 OpenTelemetry Traces 记录完整的思考路径（Prompt -> Reasoning -> Tool Call -> Result），用于 Debug “为什么它会这么想”。

5.4 安全架构 (Security)

  • 信任权衡：赋予自主权意味着风险。需采用深度防御 (Defense-in-Depth)。
    • Layer 1 确定性护栏：硬编码规则（如“交易额 > $100 需人工审批”）。
    • Layer 2 模型护栏：使用专门的小模型审查 Agent 的计划是否合规。
  • 身份管理：Agent 是新的身份类别（Principal）。需要为 Agent 分配独立的、可验证的数字身份（如 SPIFFE），并实施最小权限原则 。

⚠️ 6. 企业级落地的挑战：智能体蔓延 (Agent Sprawl)

在PPT的后半部分，重点提到了企业落地时的风险。

什么是“智能体蔓延”？

当企业内部各个团队都在独立开发Agent，且缺乏统一治理时，会出现：

  • 交互网络混乱：成百上千个Agent互相调用，难以调试。
  • 数据安全失控：Agent可能过度访问敏感数据。
  • 治理缺失：不知道哪个Agent在运行，消耗了多少Token。

解决方案框架

  • 集中式治理：建立统一的Agent注册与管理平台。
  • 标准化接口：定义Agent之间通信的标准协议（Interoperability）。
  • 安全护栏：在编排层强制加入权限校验和人类介入（Human-in-the-loop）机制。

📝 7. 前沿趋势与未来

7.1 互操作性 (Interoperability)

  • Agent 2 Agent (A2A)：不同组织的 Agent 之间通过标准化协议进行发现、握手和协作，形成 Agent 经济网络 。
  • Agent 支付：通过 Agent Payments Protocol (AP2) 和 x402 协议，赋予 Agent 经授权的支付能力，实现机器间的微支付 。

7.2 自我进化 (Self-Evolution)

  • 在岗学习：Agent 通过观察人类反馈 (HITL) 和运行日志，总结经验并更新自己的 Prompt 或知识库（如将合规性修正转化为新的规则）。
  • Agent Gym：离线的模拟训练场。通过生成合成数据和红队测试，让 Agent 在沙盒中不断试错、变强，随后再部署到生产环境 。

总结

Agent 不仅仅是自动化的延伸，它是软件开发的新范式。从构建单一助手到编排多 Agent 协作网络，成功的关键在于架构设计的严谨性——可靠的工具契约、完善的评估体系（Agent Ops）以及严格的安全边界。
